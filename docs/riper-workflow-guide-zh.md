# CursorRIPER 框架 - RIPER 工作流指南

RIPER 工作流是 CursorRIPER 框架的核心组件，通过五种不同的操作模式为软件开发提供结构化方法。本指南解释了如何有效使用每种模式。

## RIPER 工作流概述

```mermaid
flowchart LR
    R[研究 RESEARCH] --> I[创新 INNOVATE]
    I --> P[计划 PLAN]
    P --> E[执行 EXECUTE]
    E --> Rev[审查 REVIEW]
    Rev -.-> R

    style Rev fill:#f0e6ff,stroke:#6600cc
```

## 模式 1: 研究 (RESEARCH)

### 目的
收集信息并理解现有代码。

### 适用时机
- 在开始新功能或修复错误时
- 遇到不熟悉的代码时
- 需要了解某些功能如何工作时

### 命令
- `/research` 或 `ENTER RESEARCH MODE`

### 示例提示
- "我需要了解身份验证系统如何工作。"
- "你能分析支付处理模块中的数据流吗？"
- "帮我理解购物车的现有实现。"

### 最佳实践
1. 明确说明您想要了解的内容
2. 通过 @-提及相关文件提供上下文
3. 提出后续问题以加深理解
4. 在转到创新模式之前花时间彻底理解

## 模式 2: 创新 (INNOVATE)

### 目的
头脑风暴潜在方法和解决方案。

### 适用时机
- 在研究模式中收集信息后
- 探索解决问题的不同方法时
- 需要创新解决方案时

### 命令
- `/innovate` 或 `ENTER INNOVATE MODE`

### 示例提示
- "实现用户通知系统有哪些方法？"
- "让我们头脑风暴优化数据库查询的不同方法。"
- "帮我思考新功能的不同架构选项。"

### 最佳实践
1. 考虑多种方法而不是仅选择第一个想法
2. 讨论每种方法的优缺点
3. 探索不同解决方案之间的权衡
4. 暂不承诺特定实施方案
5. 记录关键决策和理由

## 模式 3: 计划 (PLAN)

### 目的
创建详细的技术规范。

### 适用时机
- 在创新模式中选择方法后
- 需要全面实施计划时
- 在进行重大代码更改之前

### 命令
- `/plan` 或 `ENTER PLAN MODE`

### 示例提示
- "为实施用户通知系统创建详细计划。"
- "让我们制定重构支付处理模块的逐步计划。"
- "帮我规划新功能的实施。"

### 规划流程
1. AI 将深入思考所需更改
2. 分析现有代码以映射更改的完整范围
3. 提出 4-6 个澄清问题以完善计划
4. 起草全面的行动计划
5. 将计划转换为编号的顺序检查表

### 最佳实践
1. 彻底回答澄清问题
2. 在批准前仔细审查计划
3. 确保计划涵盖实施的所有方面
4. 验证所有文件路径和函数名称是否正确
5. 考虑计划更改的潜在副作用

## 模式 4: 执行 (EXECUTE)

### 目的
准确实施计划模式中规划的内容。

### 适用时机
- 在计划模式中批准计划后
- 准备实施更改时
- 有明确、已批准的计划可遵循时

### 命令
- `/execute` 或 `ENTER EXECUTE MODE`

### 示例提示
- "让我们开始实施已批准的计划。"
- "实施计划中的步骤 1-3。"
- "从步骤 4 继续执行。"

### 最佳实践
1. 仅在计划获得批准后进入执行模式
2. 完全按照指定的计划进行
3. 根据检查表跟踪进度
4. 如果出现需要偏离的问题，返回计划模式
5. 随着进度更新内存库文件

## 模式 5: 审查 (REVIEW)

### 目的
根据计划验证实施情况。

### 适用时机
- 在执行模式中完成实施后
- 想要验证更改是否符合计划时
- 在提交或合并更改之前

### 命令
- `/review` 或 `ENTER REVIEW MODE`

### 示例提示
- "让我们根据计划审查实施情况。"
- "验证我们刚刚做的更改。"
- "审查步骤 1-5 以确保它们与计划匹配。"

### 最佳实践
1. 彻底审查所有更改
2. 注意任何偏差标志
3. 决定偏差是可接受的还是需要修复
4. 记录任何偏差及其理由
5. 用审查发现更新内存库文件

## 模式转换

您可以随时使用适当的命令在模式之间转换。典型的工作流遵循 RIPER 序列：

1. 从研究开始，以理解问题
2. 移至创新，探索潜在解决方案
3. 过渡到计划，创建详细的实施计划
4. 进入执行，实施计划
5. 最后，使用审查验证实施

但是，您可以根据需要在模式之间移动，除了执行模式，它需要来自计划模式的已批准计划。

## 内存库更新

随着您在 RIPER 工作流中的进展，框架将自动更新内存库文件：

- `activeContext.md` - 更新当前焦点和更改
- `progress.md` - 跟踪实施进度
- `systemPatterns.md` - 记录架构决策

保持这些文件最新，以维持会话之间的上下文。
